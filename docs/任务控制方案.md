### 🏛️ 核心架构思想：三层分离机制

要实现完美的暂停、继续和瞬间停止，必须将你的程序严格分为三层，且它们之间必须通过**线程安全的信号（Event）**来通信。

1. **UI 交互层**（主线程）：只负责接收用户点击，并向控制器发送“改变状态”的指令。**绝对不执行任何阻塞操作。**
2. **状态控制层**（全局单例）：维护当前到底处于“运行”、“挂起”还是“终止”状态。
3. **任务执行层**（子线程/Worker）：真正的自动化脚本。它在运行过程中，必须**高频次地向控制层“请示”**，根据状态决定是继续往下走、原地挂起，还是抛出异常自尽。

### 📍 第一步：建立“状态控制中心” (Task Controller)

你需要新建一个独立的模块（例如 `controller.py`），在这个模块里利用 Python 标准库的 `threading.Event` 来管理状态。

**设计规范：**

* **定义两个开关**：
* `pause_event`：负责控制暂停/继续。（`True` = 绿灯放行，`False` = 红灯停车死等）。
* `stop_event`：负责控制强行停止。（`True` = 触发销毁，`False` = 安全）。


* **定义一个异常**：`TaskStoppedException`。用于在深层嵌套的循环中，瞬间把执行流“炸”回主干。
* **一个致命细节**：当用户点击“停止”时，如果脚本正处于“暂停”状态，它处于假死期，是收不到停止信号的。所以，**“停止”动作必须同时包含“唤醒”动作**。

**核心方法草图：**

* `pause()`: `pause_event.clear()`
* `resume()`: `pause_event.set()`
* `stop()`: `stop_event.set()` 然后立刻 `pause_event.set()` (强行唤醒它去死)
* `check_status()`: 这是给自动化脚本用的。它第一步先看 `stop_event`，如果是 True，立刻 `raise TaskStoppedException`；第二步执行 `pause_event.wait()`（如果被暂停了，代码会以 0% CPU 占用永远卡在这一行，直到被唤醒）。

### 📍 第二步：打造“智能睡眠” (Smart Sleep)

这是所有写自动化脚本的人必须跨过的一道坎。
原生的 `time.sleep(10)` 是一个“黑洞”，这 10 秒内脚本对 UI 的任何点击充耳不闻。

**修改方向：**
你需要在控制器中写一个自定义的 `smart_sleep(seconds)` 函数。

* **原理**：将大的睡眠时间，切碎成无数个极小的时间片（比如 0.1 秒）。
* **动作**：在一个 `while` 循环里，每睡 0.1 秒，就调用一次上面写的 `check_status()`。
* **效果**：长达 1 分钟的等待动画中，用户随时点暂停，最多只有 0.1 秒的延迟，脚本就会响应并挂起。

### 📍 第三步：改造任务执行逻辑 (Tasks)

在这个阶段，你需要全面检查你写的 `task_gua`, `task_keye` 等所有业务函数。

**修改方向（搜索与替换）：**

1. **替换 Sleep**：全文搜索 `time.sleep`，全部替换为你自己的 `controller.smart_sleep`。
2. **埋设检查点**：在耗时较长的寻路循环（`while open_xunlu:`）或大动作之前，手动插入一句 `controller.check_status()`。
3. **取消原有的布尔值中断**：你之前写的类似于 `if not self.is_running: break` 这种逻辑可以全部删掉了，因为控制器抛出的异常会比布尔值判断更暴力、更有效。

### 📍 第四步：构建 Worker 线程的“隔离舱”

你的 `ScriptWorker`（或者继承自 `QThread` 的执行类）的 `run()` 方法，是所有任务执行的入口。这里必须建立“隔离舱”（Try-Except 块）来捕获被用户强行切断的任务。

**修改方向：**

```python
def run(self):
    # 1. 每次开新线程前，重置控制器的所有开关为“绿灯”
    controller.reset_all_events() 
    
    try:
        # 2. 依次调用你的各种 task_xxx() 
        task_A()
        task_B()
        
    except TaskStoppedException:
        # 3. 【核心】只要在任何深度的 task 中触发了停止，都会瞬间瞬移到这里！
        # 在这里执行恢复出厂设置的动作：比如清除状态提示，游戏切回主界面等。
        clean_up_game_state()
        
    except Exception as e:
        # 处理真正的代码报错
        log_error(e)
        
    finally:
        # 4. 无论如何，最后发射信号告诉 UI 线程：我彻底跑完了（或者死透了），你可以把“开始”按钮亮起来了
        self.finished_sig.emit() 

```

### 📍 第五步：对接 UI 按钮状态机

在你的 PyQt 主界面 `ClassicScriptUI` 中，按钮不再直接操控 Worker，而是向控制器发号施令。你需要维护好按钮的文字和启用状态（Enable/Disable）。

**修改方向建议：**
你可以将原本的两个按钮设计为**“双态按钮”**：

1. **主控按钮**：【开始执行】 / 【强制停止】
* 点【开始执行】：检查是否有旧线程，没有的话，启动 Worker 线程。按钮变成红色【强制停止】，并激活旁边的暂停按钮。
* 点【强制停止】：调用控制器的 `stop()` 方法。Worker 线程内部引爆异常后结束，发射 `finished_sig`。UI 收到信号后，把按钮变回【开始执行】，禁用暂停按钮。


2. **挂起按钮**：【暂停运行】 / 【继续运行】
* 点【暂停】：调用控制器 `pause()`。按钮变色为【继续运行】。
* 点【继续】：调用控制器 `resume()`。按钮变回【暂停运行】。
