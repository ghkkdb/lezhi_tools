# 新任务接入指南

本文说明当前推荐的新任务写法：新增一个任务时，只需要写任务函数，并在 `@register_task(...)` 中声明一段元信息。任务注册后，左侧任务列表、右侧参数面板、参数映射和 worker 调用会自动接上。

## 一、完整链路

新任务的自动接入链路如下：

```text
任务函数 + @register_task 元信息
        ↓
src.core.task_registry 保存 TaskMeta
        ↓
config.daily_tasks 合并旧任务列表和新注册任务
        ↓
TaskListPanel 自动渲染左侧任务复选框
        ↓
TaskConfigPanel 自动渲染右侧参数配置
        ↓
ConfigManager 收集并映射 UI 参数
        ↓
ScriptWorker 通过 get_task(task_name) 调用任务函数
```

因此，新任务一般不需要再手动修改 `src/config/task_config.py` 和 `src/config/task_definition_config.py`。旧任务仍兼容原有写法。

## 二、最小任务示例

如果任务不需要 UI 参数，只声明任务名即可：

```python
from .controller import task_controller
from .task_registry import register_task


@register_task("我的新任务", category="日常任务", order=500)
def task_my_new_task(hwnd, task_params=None):
    task_controller.check_status()

    # TODO: 在这里编写实际自动化逻辑
    # background_click(hwnd, x, y)
    # background_key(hwnd, "F")

    task_controller.smart_sleep(1)
    return True
```

任务注册后：

- `TaskListPanel` 会在左侧任务列表追加“我的新任务”。
- `ScriptWorker` 执行时会用 `get_task("我的新任务")` 找到该函数。
- 因为没有 `ui_config`，右侧不会生成参数面板。

## 三、带 UI 参数的完整示例

推荐新任务使用下面这种写法：

```python
from .controller import task_controller
from .task_registry import register_task
from src.utils.logger import get_logger


logger = get_logger("daily_tasks")


@register_task(
    "我的新任务",
    ui_config={
        "section_width": 260,
        "fields": [
            {
                "name": "config_row",
                "type": "row",
                "items": [
                    {
                        "name": "count",
                        "type": "number",
                        "label": "执行次数",
                        "default": 1,
                        "min": 1,
                        "max": 99,
                    },
                    {
                        "name": "quick_exit",
                        "type": "checkbox",
                        "label": "快速退出",
                        "default": True,
                    },
                ],
            },
            {
                "name": "mode_row",
                "type": "row",
                "items": [
                    {
                        "name": "mode",
                        "type": "dropdown",
                        "label": "执行模式",
                        "options": ["普通模式", "快速模式"],
                        "default": "普通模式",
                        "value_map": {
                            "普通模式": "normal",
                            "快速模式": "fast",
                        },
                    }
                ],
            },
        ],
    },
    category="日常任务",
    order=500,
)
def task_my_new_task(hwnd, task_params=None):
    if task_params is None:
        task_params = {}

    count = task_params.get("count", 1)
    quick_exit = task_params.get("quick_exit", True)
    mode = task_params.get("mode", "normal")

    logger.info(f"开始执行我的新任务：count={count}, quick_exit={quick_exit}, mode={mode}")

    for index in range(count):
        task_controller.check_status()

        # TODO: 在这里编写实际任务步骤
        logger.info(f"执行第 {index + 1} 次")

        task_controller.smart_sleep(1)

    if quick_exit:
        logger.info("任务启用了快速退出")

    return True
```

这里的参数流向是：

```text
ui_config.fields
        ↓
TaskConfigPanel 创建控件
        ↓
用户在 UI 中选择参数
        ↓
ConfigManager.get_task_params(...)
        ↓
config.get_task_mapped_param(...)
        ↓
ScriptWorker 调用 task_my_new_task(hwnd, task_params=params)
```

上例中，用户在 UI 选择“快速模式”后，任务函数拿到的不是中文文案，而是 `value_map` 映射后的 `"fast"`。

## 四、register_task 元信息说明

`register_task` 支持这些参数：

```python
@register_task(
    name,
    ui_config=None,
    category="日常任务",
    order=999,
    row=None,
    enabled=True,
)
```

字段含义：

| 字段 | 说明 |
| --- | --- |
| `name` | 任务显示名，也是 worker 查找任务函数的 key。必须唯一。 |
| `ui_config` | 右侧任务配置面板定义。格式沿用现有 `TaskDefinitionConfig` 的 `fields` schema。 |
| `category` | 任务分类，用于新注册任务的追加排序。 |
| `order` | 同分类内排序值，越小越靠前。旧手写任务列表仍优先展示。 |
| `row` | 同一个 `row` 值的任务会在任务布局中合并为同一行。 |
| `enabled` | 是否出现在 UI 列表中。`False` 时仍可通过 `get_task()` 获取函数，但不会自动展示。 |

## 五、UI 配置写法

`ui_config` 的基本结构如下：

```python
ui_config={
    "section_width": 260,
    "fields": [
        # 控件或布局节点
    ],
}
```

### number

```python
{
    "name": "count",
    "type": "number",
    "label": "次数",
    "default": 1,
    "min": 1,
    "max": 999,
}
```

任务函数中读取：

```python
count = task_params.get("count", 1)
```

### checkbox

```python
{
    "name": "quick_exit",
    "type": "checkbox",
    "label": "快速退出",
    "default": True,
}
```

任务函数中读取：

```python
quick_exit = task_params.get("quick_exit", True)
```

### dropdown

```python
{
    "name": "mode",
    "type": "dropdown",
    "label": "模式",
    "options": ["普通模式", "快速模式"],
    "default": "普通模式",
    "value_map": {
        "普通模式": "normal",
        "快速模式": "fast",
    },
}
```

任务函数中读取：

```python
mode = task_params.get("mode", "normal")
```

如果没有 `value_map`，任务函数拿到的是 UI 上显示的原始文本。

### text

```python
{
    "name": "keyword",
    "type": "text",
    "label": "关键字",
    "default": "",
    "placeholder": "请输入关键字",
    "width": 120,
}
```

任务函数中读取：

```python
keyword = task_params.get("keyword", "")
```

### row

`row` 用于把多个基础控件放在同一行：

```python
{
    "name": "config_row",
    "type": "row",
    "items": [
        {
            "name": "count",
            "type": "number",
            "label": "次数",
            "default": 1,
            "min": 1,
            "max": 99,
        },
        {
            "name": "quick_exit",
            "type": "checkbox",
            "label": "快速退出",
            "default": True,
        },
    ],
}
```

注意：`row` 内部只放基础控件或 `label`，不要嵌套 `row` 或 `group`。

### group

`group` 用于给一组配置加标题：

```python
{
    "name": "advanced_group",
    "type": "group",
    "label": "高级设置",
    "fields": [
        {
            "name": "retry_count",
            "type": "number",
            "label": "重试次数",
            "default": 3,
            "min": 0,
            "max": 10,
        }
    ],
}
```

注意：`group` 内部不要再嵌套子 `group`。

### label

```python
{
    "name": "notice",
    "type": "label",
    "text": "提示：只会执行当前勾选任务。",
    "style": "info",
}
```

`label` 只显示说明，不会进入 `task_params`。

## 六、同排展示多个任务

如果希望多个新任务在布局中合并为一行，给它们相同的 `row`：

```python
@register_task("任务A", category="日常任务", order=600, row="my_task_row")
def task_a(hwnd, task_params=None):
    return True


@register_task("任务B", category="日常任务", order=610, row="my_task_row")
def task_b(hwnd, task_params=None):
    return True
```

最终 `config.daily_tasks` 会把它们追加为类似：

```python
["任务A", "任务B"]
```

旧的 `src/config/task_config.py` 中已经手写的任务列表仍然优先，新注册任务只会追加没有出现过的任务名。

## 七、任务函数规范

推荐任务函数签名：

```python
def task_xxx(hwnd, task_params=None):
    ...
```

任务函数中建议遵守：

- `task_params` 为空时转成 `{}`。
- 长等待使用 `task_controller.smart_sleep()`。
- 循环、长流程、图像等待前后调用 `task_controller.check_status()`。
- 成功返回 `True`。
- 失败返回 `False` 或抛出已有任务异常。
- 不要在任务中直接长时间 `time.sleep()`，否则暂停和停止响应会变慢。

推荐模板：

```python
@register_task("模板任务", category="日常任务", order=900)
def task_template(hwnd, task_params=None):
    if task_params is None:
        task_params = {}

    task_controller.check_status()

    try:
        # TODO: 执行任务逻辑
        task_controller.smart_sleep(1)
        return True
    except Exception as exc:
        logger.exception(f"模板任务执行失败: {exc}")
        return False
```

## 八、放到新模块时的导入要求

注册装饰器只有在模块被导入时才会执行。

当前 `ScriptWorker` 会导入 `src.core.daily_tasks` 来触发旧任务注册。如果你把新任务写在 `daily_tasks.py` 中，不需要额外处理。

如果你把任务放到新模块，例如：

```text
src/core/tasks/my_new_tasks.py
```

需要确保启动时导入该模块。推荐后续建立统一任务包：

```python
# src/core/tasks/__init__.py
from . import my_new_tasks  # noqa: F401
```

然后在 worker 中导入统一任务包：

```python
from . import tasks  # noqa: F401
```

否则任务函数不会进入注册表，UI 也无法自动展示。

## 九、旧配置的兼容规则

当前兼容策略如下：

- 旧的 `TaskConfig.daily_tasks` 仍然有效。
- 旧的 `TaskDefinitionConfig.definitions` 仍然有效。
- 如果同一个任务名同时存在旧 UI 配置和新 `ui_config`，旧 UI 配置优先。
- 用户已保存方案仍使用原格式：

```json
{
  "checked_tasks": ["我的新任务"],
  "task_params": {
    "我的新任务": {
      "count": 1,
      "quick_exit": true,
      "mode": "普通模式"
    }
  }
}
```

执行前，`ConfigManager` 会把保存的原始 UI 值通过 `value_map` 转成任务函数实际需要的值。

## 十一、排查清单

如果任务没有出现在 UI 中，按顺序检查：

1. 任务模块是否真的被导入。
2. `@register_task(...)` 的 `enabled` 是否为 `True`。
3. 任务名是否和保存方案、日志中使用的名字一致。
4. 如果任务已在旧 `daily_tasks` 中出现，新注册任务不会重复追加。

如果任务出现了但没有参数面板：

1. 是否传入了 `ui_config`。
2. `ui_config` 是否包含 `fields`。
3. 控件类型是否为现有支持类型：`dropdown`、`text`、`number`、`checkbox`、`spinbox`、`label`、`row`、`group`、`columns`。

如果参数值不符合预期：

1. 检查 `name` 是否和任务函数中的 `task_params.get(...)` 一致。
2. 检查 `value_map` 的 key 是否和 `options` 中的显示文本完全一致。
3. 检查是否存在同名旧 UI 配置；旧配置会优先于注册表里的 `ui_config`。
