这套准则的核心目的只有三个：**绝对防卡死、极低 CPU 占用、状态绝对可靠**。

---

### 📏 自动化任务编写五大准则

#### 1. 绝对防御：消灭无限制的 `while` 循环

* **反面教材**：`while True:` 或 `while 找不到图:`（一旦卡模型、掉线、UI未响应，脚本就死在这里了）。
* **标准做法**：无论是整个任务的大循环，还是寻路、等动画的小循环，**必须全部改用带明确上限的 `for` 循环**。结合 `time.sleep` 计算出最大等待时间（例如 `for i in range(12): sleep(5)` 就是最多等 60 秒）。超时后必须有 `break` 或 `continue` 进行兜底重置。

#### 2. 性能至上：使用“短路求值”释放 CPU

* **反面教材**：在一个循环里平行写 10 个 `pos = find_image(...)`。就算当前是第 1 个状态，程序也会强行去搜后面 9 张图，导致 CPU 占用率飙升。
* **标准做法**：对于**互斥**的界面状态，使用 `if ... elif ... elif ...` 配合 Python 的海象运算符 `:=`（或分开写）。一旦匹配到当前状态，立即执行对应点击，并进入下一轮循环。

#### 3. 闭环验证：眼见为实，不迷信“动作”

* **反面教材**：点击了“摇树”或“领奖”坐标，就直接 `return True` 宣布任务完成。
* **标准做法**：动作做完不算完，必须**回到任务列表/活动菜单，确认该任务的入口彻底消失**（返回 None），才算真正的完成。这能完美兼容“一天要做多次”、“网络延迟导致点击失效”等突发情况。

#### 4. 心跳检测：多分支执行阶段的防发呆机制

* **场景**：在打怪、答题、复杂对话等多状态流转时。
* **标准做法**：设置一个 `last_action_time = time.time()`。只要成功点了一个按钮，就重置这个时间。如果循环在运转，但连续 30 秒没有任何实质性点击（即没有任何 `elif` 被触发），则判定为“发呆卡死”，立刻触发自救（如关闭所有窗口重新来过）。对于什么都不做的空轮次，**必须加上 `time.sleep(1)` 释放 CPU**。

#### 5. 统一通讯：标准化的 `True/False` 握手

* **标准做法**：函数只返回两种结果：
* `return True`：任务**彻底、干净地完成**，或者因为没有次数/未开启而**合法结束**。主控程序可以直接切下一个任务。
* `return False`：任务在达到了**最大重试次数**后依然无法推进（严重 Bug 或长期掉线）。主控程序收到后应该报警或执行全局重启。

### 📝 终极通用任务模板 (Task Template)

你可以把下面这段代码作为一个 Snippet（代码片段）保存在你的编辑器里，以后写新任务，直接复制这个架子往里面填逻辑即可。

```python
import time

def task_template(hwnd, log_signal=None):
    """
    [任务名称] 任务通用模板
    """
    task_name = "某某任务"
    logger.info(f"正在处理: {task_name}")
    
    # 1. 全局配置
    max_task_attempts = 3   # 任务大循环最大重试次数
    timeout_idle = 30       # 执行阶段的心跳超时时间（秒）

    for attempt in range(1, max_task_attempts + 1):
        if attempt > 1:
            logger.debug(f"{task_name}：进行第 {attempt} 次重新尝试")
            
        # 2. 环境清理与接取确认 (闭环验证核心)
        win_gb(hwnd)        # 清理意外弹窗
        zhd(hwnd)           # 打开活动菜单/任务列表
        time.sleep(1)
        
        # 【填空1】识别活动菜单中的任务入口
        img_rukou = config.get_img_path("...")
        pos_rukou = find_image(hwnd, img_rukou, threshold=0.8)
        
        if pos_rukou is None:
            logger.success(f"{task_name} 任务彻底完成 (或未开启)")
            win_gb(hwnd)
            return True     # 唯一正常出口
            
        # 点击前往接取任务
        background_click(hwnd, pos_rukou[0], pos_rukou[1], button="left", delay=60)
        time.sleep(3)

        # 3. 寻路/加载等待阶段 (超时保护)
        max_find_attempts = 12
        pathfinding_success = False
        
        for i in range(max_find_attempts):
            # 【填空2】识别是否到达目的地（例如识别到了目标NPC或副本内特有UI）
            img_mubiao = config.get_img_path("...")
            pos_mubiao = find_image(hwnd, img_mubiao, threshold=0.8)
            
            if pos_mubiao is None:
                logger.debug(f"{task_name} 寻路/加载中... ({i+1}/{max_find_attempts})")
                time.sleep(5) # 每次等5秒，最多等60秒
            else:
                logger.info("成功到达目的地")
                pathfinding_success = True
                break
                
        if not pathfinding_success:
            logger.warning("寻路/加载超时，重置任务流程...")
            continue        # 放弃本轮，回到 for 循环开头重新确认任务

        # 4. 任务核心执行阶段 (心跳检测 + 短路求值优化)
        logger.info(f"开始执行 {task_name} 核心逻辑...")
        last_action_time = time.time()
        task_finished_this_round = False
        
        # 【填空3】提前缓存执行阶段需要用到的所有图片路径
        img_state_A = config.get_img_path("...") # 例如：对话按钮
        img_state_B = config.get_img_path("...") # 例如：提交道具按钮
        img_state_C = config.get_img_path("...") # 例如：战斗结束按钮
        
        while time.time() - last_action_time < timeout_idle:
            baoguo_manSet(hwnd) # 处理通用的意外状态（如包裹满）
            
            # 使用海象运算符 (:=) 进行短路求值，按出现频率从高到低排列
            if pos := find_image(hwnd, img_state_A, threshold=0.8):
                background_click(hwnd, pos[0], pos[1], button="left", delay=60)
                time.sleep(2)
                last_action_time = time.time() # 产生有效动作，重置心跳
                
            elif pos := find_image(hwnd, img_state_B, threshold=0.8):
                background_click(hwnd, pos[0], pos[1], button="left", delay=60)
                time.sleep(3)
                last_action_time = time.time()
                
            elif pos := find_image(hwnd, img_state_C, threshold=0.8):
                logger.info("单轮流程结束退出")
                background_click(hwnd, pos[0], pos[1], button="left", delay=60)
                time.sleep(3)
                task_finished_this_round = True
                break # 成功完成本轮动作，跳出内部循环
                
            else:
                # 【关键性能保护】当前画面没有匹配到任何已知状态，必须 sleep 释放 CPU！
                time.sleep(1)
                
        # 5. 执行轮次结算
        if task_finished_this_round:
            logger.info("本轮执行完毕，返回活动菜单进行闭环验证...")
            win_gb(hwnd)
            continue # 正常做完，通过 continue 回到大循环开头的 zhd() 去验证入口是否消失
        else:
            logger.warning(f"{task_name} 核心执行阶段发呆超时({timeout_idle}秒)，尝试重置...")
            win_gb(hwnd)
            # 可选：这里可以加上 TuiLIKaShi_set(hwnd) 等脱离卡死操作
            continue

    # 6. 异常兜底出口
    logger.error(f"{task_name} 任务执行异常，已达最大重试次数 ({max_task_attempts}次)")
    win_gb(hwnd)
    return False

```

以后写任何新的日常，只要把图片路径和对应的点击逻辑填进这个框架里，写出来的脚本天然就是高稳定、低占用、自带防卡死的工业级水准！
